# Профили vLLM

Каждая папка — один квант: его профиль, привязка к модели и служба, плюс замер этого кванта. Профили запускаются лаунчером форка `weicj/vLLM-2080Ti-Definitive`, ветка `0.1.x`.

**Важно про `PROFILE`.** Путь указывается **относительно каталога `profiles/` и целиком** — короткое имя молча уводит лаунчер в чужой автоподбор, и вы получите не тот конфиг, который читаете. Проверено на своей шкуре.

**Цифры ниже сняты на ветке `0.1.x`.** На `0.2.1-pre3` те же две первые строки дают 87.0 / **99.6** / 88.0 и 70.1 / **89.2** / 71.5 — профили при этом зеркальные, менялась только версия движка. Подробности в [`../README.md`](../README.md).

## Что эта таблица говорит

**Восемь бит на Turing стоят 40% скорости.** 55.1 против 79.7 у четырёхбитного AWQ на той же модели. Причина не в кванте как таковом, а в архитектуре карт: на SM75 путь INT8 не оптимизирован. Отдельный замер Quark-INT8 W8A8 дал 15.7 против 113 у AWQ — в семь раз.

**Настоящий `awq` не быстрее `compressed-tensors`.** Ставился специально ради проверки: 64.5 против 79.7 на коде. Формат сам по себе ничего не решает, решает конкретная сборка весов.

**Свой квант по рецепту чемпиона не догнал готовый.** 69.0 против 79.7. То есть разрыв между 3.6 и 3.8 создаёт не рецепт квантования.

**Разрыв 3.6 против 3.8 — архитектурный.** У Qwen3.8 часть слоёв SSM/Gated Delta Net, и движок из-за них раздувает блок внимания до 816 токенов, а поддержку префиксного кэша для них сам называет экспериментальной. Никакой квант это не уберёт.

## Общее для всех профилей

- `GPU_UTIL=0.94` — не 0.90: на девяноста не хватало 90 МиБ под KV-кэш при контексте 256K.
- `MTP_K=4` — четвёрка обыграла тройку; `MTP_K=0` в профиле `nomtp` оставлен для замера цены самой головы.
- `MAX_NUM_SEQS=2` — стенд под одиночные запросы, не под пакетную выдачу.
- Тензорный параллелизм TP=2 задаёт сам лаунчер (`--tensor-parallel-size ${TP_SIZE:-2}`), NVLink живой: `GPU0 ↔ GPU1 = NV2`, два линка по 25.78 ГБ/с.
- int8 KV-кэш **не включать**: замерено, вредит скорости.
