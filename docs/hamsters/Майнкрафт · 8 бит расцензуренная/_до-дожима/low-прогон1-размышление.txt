Now for the value noise:
```
function smoothstep(t) { return t * t * (3 - 2 * t); }

function noise2(x, y) {
    const xi = Math.floor(x), yi = Math.floor(y);
    const xf = x - xi, yf = y - yi;
    const u = smoothstep(xf), v = smoothstep(yf);
    const a = hash2(xi, yi);
    const b = hash2(xi + 1, yi);
    const c = hash2(xi, yi + 1);
    const d = hash2(xi + 1, yi + 1);
    return a + (b - a) * u + (c - a) * v + (a - b - c + d) * u * v;
}

function fractal2(x, y) {
    let val = 0, amp = 1, freq = 1, total = 0;
    for (let i = 0; i < 4; i++) {
        val += noise2(x * freq, y * freq) * amp;
        total += amp;
        amp *= 0.5;
        freq *= 2;
    }
    return val / total;
}
```

```javascript
function hash2(x, y) {
    let n = (x * 374761393 + y * 668265263) | 0;
    n = ((n ^ (n >>> 13)) * 1274126177) | 0;
    n = (n ^ (n >>> 16)) | 0;

}
```

This should give values in [0, 1]. The `| 0` forces 32-bit signed integer, and `& 0x7fffffff` gives the absolute value (well, the positive range). Dividing by 0x7fffffff gives [0, 1].

For 3D:
```javascript
function hash3(x, y, z) {
    let n = (x * 374761393 + y * 668265263 + z * 1440662683) | 0;
    n = ((n ^ (n >>> 13)) * 1274126177) | 0;
    n = (n ^ (n >>> 16)) | 0;
    return (n & 0x7fffffff) / 0x7fffffff;
}
```

Now, one potential issue: when x and y are large (like 10000), x * 374761393 could overflow 32 bits before the `| 0`. In JavaScript, multiplication of two numbers that fit in 32 bits can produce a result up to about 2^62, which is within the safe integer range for doubles. But when we do `| 0`, it truncates to 32 bits. So the sequence is:
1. Compute x * 374761393 + y * 668265263 as a double (exact for reasonable inputs)
2. `| 0` truncates to 32-bit signed int
3. XOR and multiply again, `| 0` again
4. Final XOR, `| 0`
5. Take positive range

This should work correctly for the range of coordinates we'll encounter (within a few thousand).
