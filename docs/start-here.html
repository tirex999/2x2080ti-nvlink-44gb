Купил две 2080 Ti — что делать дальше

Пошагово, с нуля. Каждая команда проверена на нашем стенде, а не переписана из интернета. Где что-то может пойти не так — сказано, как это выглядит.

Всего шагов пять, времени — час-полтора, из которых почти всё это скачивание.

Шаг 0. Что должно быть до начала

  • Две RTX 2080 Ti. Обычные на 11 ГБ тоже работают, но модель на 27 миллиардов параметров в 22 ГБ суммарно не влезет — нужны моддированные на 22 ГБ каждая (итого 44 ГБ). У нас именно такие.
  • NVLink желателен, но не обязателен: мы мерили, для vLLM он даёт прирост, для llama.cpp не даёт ничего.
  • Материнская плата, где обе карты получают хотя бы x8. Карты двухслотовые, между слотами нужен зазор — иначе верхняя задыхается.
  • Блок питания с запасом: две 2080 Ti под нагрузкой берут около 500 Вт вдвоём.

Проверить, что система вообще видит карты, до всякой установки:

lspci | grep -i nvidia

Должны быть две строки с VGA compatible controller. Нет двух — дальше идти бессмысленно, это железо, а не софт.

Шаг 1. Система

Ставьте Ubuntu 24.04. Причина одна и простая: под неё есть готовая сборка, которую не надо компилировать.

система готовая сборка почему
Ubuntu 24.04 работает python 3.12 и glibc 2.39 — то, что нужно
Ubuntu 26.04, Debian 13 работает ещё новее
Ubuntu 22.04 не работает python 3.10 (нужен 3.12) и glibc 2.35 (нужен 2.38)

На 22.04 придётся собирать движок самому — это несколько часов и отдельная возня с версиями компилятора. Возможно, но новичку не надо.

Проверить свою систему:

lsb_release -d          # какая система
python3 --version       # должно быть 3.12.x
ldd --version | head -1 # должно быть 2.38 или больше

Шаг 2. Драйвер NVIDIA

Это самый частый источник путаницы, поэтому подробно.

Что ставить

Только установщик .run с сайта NVIDIA. Не пакет из репозитория дистрибутива: он почти всегда старее, чем нужно, и потом придётся разбираться, почему CUDA не видит карт.

Нужна версия не ниже 580 — с неё начинается поддержка CUDA 13. У нас стоит 610.43.02, на ней всё замерено.

Как поставить

# 1. скачать (440 МБ)
wget https://us.download.nvidia.com/XFree86/Linux-x86_64/610.43.02/NVIDIA-Linux-x86_64-610.43.02.run
chmod +x NVIDIA-Linux-x86_64-610.43.02.run

# 2. выключить встроенный драйвер nouveau, иначе установщик откажется
sudo bash -c 'echo -e "blacklist nouveau\noptions nouveau modeset=0" > /etc/modprobe.d/blacklist-nouveau.conf'
sudo update-initramfs -u
sudo reboot

# 3. после перезагрузки — поставить
sudo ./NVIDIA-Linux-x86_64-610.43.02.run --silent

Проверить

nvidia-smi

Должно показать обе карты. Правильный вывод выглядит так:

0, NVIDIA GeForce RTX 2080 Ti, 22528 MiB, 610.43.02, 7.5
1, NVIDIA GeForce RTX 2080 Ti, 22528 MiB, 610.43.02, 7.5

Смотрите на три вещи:

  • 22528 MiB — карта показывает свои 22 ГБ. Показывает 11264 — значит мод не применён или биос не тот; это к продавцу карт, драйвер тут ни при чём.
  • 7.5 — это sm_75, архитектура Turing. Именно под неё сделана сборка.
  • В шапке nvidia-smi строка CUDA UMD Version: 13.3 — драйвер умеет CUDA 13.

Отдельно: если у вас Proxmox или другие контейнеры

Тут ловушка, на которой легко потерять вечер. Драйвер состоит из двух частей, и они живут в разных местах:

  • модуль ядра — только на хосте, там где реальное железо;
  • библиотеки — внутри каждого контейнера, где будет крутиться модель.

Проброс устройств в контейнер сам по себе ничего не даёт: /dev/nvidia0 появится, а nvidia-smi скажет «команда не найдена». Внутрь контейнера надо поставить тот же самый установщик, но без модуля ядра:

# внутри контейнера, тем же файлом .run той же версии
./NVIDIA-Linux-x86_64-610.43.02.run --no-kernel-module --silent

Версия обязана совпадать с хостовой до последней цифры. После этого nvidia-smi в контейнере покажет карты. Проверено ровно так.

Драйвер к версии Ubuntu внутри контейнера отношения не имеет: у нас хост вообще на Debian 13, а контейнер на Ubuntu — и всё работает.

Шаг 3. Движок — одной командой

Компилятор, CUDA-тулкит и заголовки не нужны: всё уже собрано.

curl -LO https://raw.githubusercontent.com/tirex999/2x2080ti-nvlink-44gb/main/scripts/install.sh
bash install.sh

Скрипт сначала проверит машину и, если что-то не так, скажет что именно и что делать вместо. Потом скачает готовую сборку и поставит зависимости. Дольше всего идёт torch — несколько гигабайт.

Хотите сперва просто проверить машину, ничего не устанавливая:

bash install.sh --check

Шаг 4. Модель

Скачать можно тем же скриптом:

bash install.sh --model twolven/Qwen3.8-27B-abliterated-AWQ-MTP

Что брать — зависит от задачи. Все числа наши, замерены на двух 2080 Ti, порядок такой: проза / код / повтор, токенов в секунду.

хочу брать скорость вес
максимум скорости QuantTrio/Qwen3.6-27B-AWQ 87.0 / 99.6 / 88.0 20 ГБ
самую умную из быстрых twolven/Qwen3.8-27B-abliterated-AWQ-MTP 70.1 / 89.2 / 71.5 19 ГБ
точность важнее скорости lued/Qwen3.8-27B-INT8-W8A16-MTP 57.3 / 71.3 / 64.4 30 ГБ

Начинайте со второй: она умнее первой и заметно быстрее третьей.

Шаг 5. Запуск

source ~/vllm-2080ti/venv/bin/activate

python -m vllm.entrypoints.openai.api_server \
  --model ~/vllm-2080ti/models/Qwen3.8-27B-abliterated-AWQ-MTP \
  --host 0.0.0.0 --port 8000 \
  --tensor-parallel-size 2 \
  --dtype half \
  --gpu-memory-utilization 0.94 \
  --max-model-len 102400 \
  --max-num-seqs 1 \
  --speculative-config '{"method":"mtp","num_speculative_tokens":4}' \
  --enable-auto-tool-choice --tool-call-parser qwen3_xml \
  --enable-force-include-usage

Что тут важно и почему — по порядку, это не украшения:

  • --tensor-parallel-size 2 — использовать обе карты. Без него модель просто не влезет.
  • --gpu-memory-utilization 0.94 — не 0.90: на девяноста нам не хватало 90 МиБ под кэш при большом контексте.
  • --max-num-seqs 1 — не ради экономии. Батч больше единицы вместе с ускорителем MTP и CUDA-графом роняет сервер на Turing с ошибкой illegal memory access. Мы на этом потеряли утро.
  • --speculative-config ... mtp — главный рычаг скорости. Без него та же модель даёт 27 t/s вместо 100+. Не выключайте.
  • --enable-auto-tool-choice и --tool-call-parser — нужны, если будете подключать веб-интерфейс: он шлёт запросы с инструментами, и без этих ключей сервер отвечает ошибкой на второе же сообщение.
  • --enable-force-include-usage — чтобы интерфейс показывал счётчик токенов.

Первый запуск долгий: модель грузится с диска в видеопамять, это минуты. Готовность видна по строке Application startup complete.

Проверить:

curl localhost:8000/v1/models

Шаг 6. Чтобы этим можно было пользоваться как чатом

Поднимите Open WebUI:

docker run -d -p 8080:8080 \
  -v open-webui:/app/backend/data \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main

Дальше в интерфейсе: Настройки → Соединения → добавить OpenAI-совместимое, адрес http://АДРЕС_СЕРВЕРА:8000/v1, ключ любой непустой, например local.

Сразу положите постоянный ключ подписи сессий, иначе каждый перезапуск будет разлогинивать всех, и это выглядит как «пропала учётная запись»:

D=/var/lib/docker/volumes/open-webui_open-webui-data/_data
head -c 32 /dev/urandom | base64 | tr -d '\n' > "$D/.webui_secret_key"
chmod 600 "$D/.webui_secret_key"

Как понять, что всё хорошо

Включите статистику сервера (--disable-log-stats не ставить) и смотрите журнал. Строка выглядит так:

Avg generation throughput: 89.0 tokens/s, Running: 1 reqs, GPU KV cache usage: 22.9%
SpecDecoding metrics: Mean acceptance length: 3.76, Drafted throughput: 94.78 tokens/s,
                      Avg Draft acceptance rate: 68.9%

Скорость гуляет от 45 до 120 — это нормально, и вот почему. Она равна

длина принятого черновика × число проходов модели в секунду

Второй множитель — константа вашего железа, у нас 23.3 прохода в секунду. Первый зависит от текста: на коде черновик угадывает 97 % и снимается почти 5 токенов за проход, отсюда 120; на рассуждениях угадывает каждый пятый, снимается 1.9, отсюда 45.

Если получилось 16–20 t/s

Это три разные болезни, и лечатся по-разному. Проверяйте по порядку:

  1. Квантованы ли активации. Загляните в quantization_config модели. W8A8, quark, fp8 с квантованными активациями — падение в семь раз, до 15.7 t/s. На Turing этот путь не оптимизирован. Лечение — взять W8A16 или, лучше, четырёхбитный AWQ.
  2. Включён ли MTP. Если в журнале нет строк SpecDecoding metrics — черновика нет, и потолок втрое ниже.
  3. Длинный ли контекст. С ростом контекста падает число проходов в секунду — это уже не про квант.

Одна цифра «16 t/s» эти случаи не различает.
